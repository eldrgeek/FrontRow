## Weak, not changed here

- **The socket server trusts every client.** `artist-go-live`, `reset-show`, `artist-end-show` and the house-manager events have no sign-in check. The LiveKit performer token is gated (a stranger cannot publish video), but a stranger with the dev tools open can still end a set. This branch narrows it (a connected performer cannot be displaced), and the real fix is to verify the Supabase session on the socket.
- **The front page is still the compiled "Jess Wayne, Friday 8:00 pm"** unless a performances row replaces it. I could not read the production table from here. If Hootnet wants its own bill, add a performance in `/build/front-row` before the night.
- **LiveKit is still LiveKit Cloud.** Mike's ruling is the VPS. Moving it changes three places at the same moment and is its own gated change. Not before Hootnet.
- **One performer at a time.** A song circle wants a line for the stage (the spec's hand queue: one floor, offers, passes). This branch gives the base for it (one holder, a stage that frees itself) but not the line.
- **Not built from the agreed room rules:** closed room with invites, direct channels, breakouts, screen sharing, Full record. These belong to SOMA Rooms inside the venue (phase 4), not to the theater's house.
- **Lint has 65 standing problems** and the repo carries many old test scripts and docs at the top level.

## What needs deploying, and what the preview shows

The Netlify preview runs this branch's page against **production's** socket server. So on the preview you can try rows 4 to 7. Rows 1 to 3 are server changes in `server/index.js` and `server/rooms.js`; they take effect when `frontrow-server` on the VPS gets the two files and a restart (runbook step 5 in `THEATER-KIT-RELEASE.md`). The new page is safe against the old server, and the new server is safe with the old page.

One caution with the old server: the new page no longer clears a stuck "live" stage by itself. The green room shows "Someone is on stage right now" with a "Nobody is performing: clear the stage" link, which does what every page load used to do.
